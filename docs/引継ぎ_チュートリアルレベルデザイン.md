## 1. ⚠️ 仕様書と実装がずれている箇所（最初に確認してほしい）

**§11.1 の表にある `pogo_authority` が、仕様書 0.93 に対して実装は 0.40。**

```
docs/pogo_game_spec_v0.2.md §11.1
  restitution 0.18 + pogo_authority 0.93 | 斜面で弾き飛ばされない。角度は地形ではなく自分で作る

resources/pogo_stats_default.tres（実値）
  restitution = 0.18
  pogo_authority = 0.4      ← ここ
```

`pogo_authority` は射出方向の主導権で、**1.0 = 傾き角そのまま / 0.0 = 純粋な地形反射**です
（`scripts/pogo_stats.gd:38`）。0.40 だと**地形の反射のほうが強く効きます**。

仕様書の「角度は地形ではなく自分で作る」という中核の主張は 0.93 を前提に書かれています。
0.40 のままなら、**斜面の角度がそのまま跳ぶ向きに効く**ので、
「坂の置き方で誘導する」設計が有効になり、逆に「平地で傾きだけを教える」は弱くなります。

**どちらを正とするかで、チュートリアルで教えるべきことが変わります。**
作業を始める前にここを決めてください。他の数値（restitution 0.18 / tilt_limit 35 /
tilt_speed 30 / gravity 450 / charge_hold_time 0.25 / air_control 20 /
ground_normal_threshold -0.85）は仕様書と実装が一致していました。

## 2. 寸法の目安

### グリッド

実行中 `F4`、編集中は `addons/design_grid` プラグインで、**250px** の方眼が出ます。
`scripts/design_grid.gd` のコメントにある実測値:

| | 高さ | マス換算 |
|---|---|---|
| 普通に跳んでチャージで届く高さ | **282px** | 約 1 マス |
| 飛び込み台（落差）を使って届く高さ | **最大 568px** | 約 2.3 マス |

> **注意** … この2つは実測値ですが、いつ測ったものか記録がありません。
> §1 の `pogo_authority` の件と合わせて、**着手時に測り直すことをおすすめします**。
> 測り方は §5 にあります。

### 足場として成立する角度

`ground_normal_threshold = -0.85` → **約32°より急な面は壁扱い**になり、
触れると `wall_bounce_scale = 0.39` まで減速して滑り落ちます。
**足場にできるのは緩斜面だけ**です。

### 方向転換にかかる時間

`tilt_speed = 30°/秒`、`tilt_limit = 35°` なので、**左右の反転に約2.3秒**かかります。
`air_control = 20` で滞空1秒あたり±10px しか動かせないため、**空中の立て直しはほぼ効きません**。

→ このゲームは「**先を読んで、長い滞空の間に角度を作り込み、あとは委ねる**」のが中核です
（仕様書 §11.1）。瞬間的な操作で立て直す設計は、数値上できないので作っても機能しません。

### ⚠️ 看板の表記が実装と合っていません

画像には「**WASDで移動**」と描かれていますが、入力マップに割り当てがあるのは
**`A` / `D` / `←` / `→` だけ**です。`W` と `S` は何もしません（`project.godot` の `[input]`）。

さらに `A`/`D` は「移動」ではなく「**傾き**」です。初めての人が W で跳ぼうとして
反応せず、A/D で歩こうとして跳ね続ける、という最初の躓きが起きる状態です。
**チュートリアル作業で最優先に直す対象だと思います。**

## 4. ステージの作り方

### ノード構成

```
Stage (stage.gd)
├── CameraBounds   Polygon2D（4点）  ← カメラ範囲 ＝ 落下死の線
├── Spawn          Marker2D          ← 開始位置
├── RecoveryPoints Node2D
│   └── Point1..N  Marker2D          ← 復帰地点（通過順に記録、巻き戻らない）
├── Terrain        StaticBody2D
│   └── *          CollisionPolygon2D + terrain_polygon.gd   ← 当たり判定
├── Hazards        Area2D + hazard.gd（任意）                ← 触れると落下扱い。赤系の色で
├── Goal           Area2D + goal.gd                          ← 大好物。触れたらクリア
├── Graphics       Node2D
│   └── Gfx_*      Polygon2D + terrain_sprite.gd             ← 見た目（タイル貼り）
└── BackGraphics   Node2D                                    ← 看板など
```

`stage.gd` のクラスコメントは Terrain / Goal / Spawn しか書いていませんが、**実際は上記です**。

### 地形を作る → 絵を貼る の順

1. `Terrain` の下に `CollisionPolygon2D`（スクリプト `terrain_polygon.gd`）を置き、
   エディタの「ポリゴンを編集」で形を作る。**当たり判定と塗りつぶしが同じ頂点データ**なのでズレません
2. 形が決まったら、下のツールで `Graphics/Gfx_*` を自動生成する

```
godot --headless --path <プロジェクト> --script res://tools/make_terrain_sprites.gd \
    -- res://scenes/stages/Stage01.tscn
```

**作り直しても貼った絵は消えません。** 同名の `TerrainSprite` があれば形と位置だけ更新し、
`texture` / `tile_size` / `mirror_tiling` は触りません。
「一度走らせて絵を割り当て → 地形を直す → 走らせ直す」の順で使えます。

個別に形を合わせ直したいときは、`TerrainSprite` の `copy_from` にコリジョンを指定します。

### camera_bounds の落とし穴（仕様書 §10 より）

`Rect2` なので、**上端だけ広げるつもりで `position.y` だけ動かすと下端も一緒に下がります**。
`size.y` も合わせて増やさないと、「開始した瞬間に落下死する」という追いにくい事故になります。

読み込み時に自動チェックが走り、①開始位置・復帰地点が死の線より下、
②地形が `camera_bounds`（+64px の余裕）からはみ出している、の2点を警告します。
**地形を広げたら camera_bounds も必ず合わせること。**

## 5. 動作確認のしかた

### デバッグキー（`Game.debug_shortcuts` が true のとき）

| キー | 働き |
|---|---|
| `F1` | POGO TUNER。**実行中にパラメータをスライダーで変えられる**。調整の主力 |
| `F2` | ステージセレクト |
| `F3` | 現在のステージを強制クリア（スコアは送信しません） |
| `F4` | 方眼の表示切替（250px） |
| `F6` | イベントセレクト |
| `R` | ステージをやり直す（タイムもリセット） |
| `1`〜`9` / `0` | ステージへ直接ジャンプ |

### 跳躍の高さ・距離を測り直す

§2 の 282px / 568px を測り直すなら、ヘッドレスの計測ハーネスが使えます。

```
godot --headless --path <プロジェクト> scenes/AutoplayDebug.tscn
```

右キーを押しっぱなしで自動再生し、**5フレームごとに位置・速度・傾きを出力**します
（`scripts/autoplay_debug.gd`）。出力の y の最小値から到達高さが取れます。
チャージ操作は入っていないので、ためジャンプを測るなら `Input.action_press(&"pogo_charge")`
を足す改造が要ります。

### 絵を描く前に形だけで通す

`terrain_polygon.gd` は塗りつぶしを自分で描くので、**`Graphics` を作らなくても
色付きの形のまま遊べます**。レイアウトの検証はこの状態で回すのが速いはずです。

## 8. 配布前に戻すもの（レベルデザインとは別件）

デバッグ用に有効化されたままの設定が2つあります。チュートリアル作業中はむしろ必要なので、
**作業中はそのままで構いませんが、完成時に戻してください**。

| 場所 | 現状 | 戻す値 |
|---|---|---|
| `scenes/Main.tscn` Main ノード `show_cutscene_notes` | `true` | `false`（台本の〔演出：…〕がプレイヤーに見えます） |
| `Game.debug_shortcuts` | `true` | `false`（ランキングに出鱈目な記録が載ります） |

どちらもインスペクタの ↺ でシーンの上書きを消せば既定値に戻ります。
書き出しプリセットのカスタム機能に `testplay` が付いていると `debug_shortcuts` は
自動で false になりますが、通常の配布用プリセットでは手で確認が要ります。
