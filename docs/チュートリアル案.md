# チュートリアル案（独立したチュートリアル面）

1ステージで、基本操作・連続ジャンプ・溜めジャンプ・着地位置による違いまでを教えきる案。
テストプレイのフィードバック（八神トオルさん／palook大槻さん／テスター3）への対応も、
この面で拾えるぶんはここに畳み込んである。

**置きかた（決定済み）**

- **既存の10ステージには手を入れない。** チュートリアルは番号を持たない別の面として追加する
- タイトルに **TUTORIAL** を足し、そこから始める
- チュートリアル面をクリアすると、**OP を挟んで本編のステージ1へ繋がる**
- 実装は §9 を参照。シーンは `scenes/stages/StageTutorial.tscn`

- 前提資料: `docs/引継ぎ_チュートリアルレベルデザイン.md`、`docs/pogo_game_spec_v0.2.md` §10/§11、`docs/あそびかた.md`
- この案の数値は **Godot ヘッドレスで実測した** もの（§1）。引継ぎ資料で「測り直すことを勧める」としていた
  282px / 568px もここで確定させた

---

## 0. 結論だけ先に

1. **チュートリアルの背骨は「溜めを押しっぱなしにすると、跳ぶたびに高くなる」。** これが分かると登れる。
   分からないと登れない。現状のチュートリアル看板はこれを一言も説明していない
2. **1マス（250px）の階段は、溜め押しっぱなしでも登り切れない**（実測。どの条件でも数段で頭打ち）。 同じ段で2〜3回跳ね直して高さを溜めてから
   次の段へ移るのが正しい登りかた。八神さんの「2度目のほうが高く飛べる」はこれのこと。
   **ここを教えるのがチュートリアルの最大の仕事**
3. 看板3枚（`Tutorial1〜3.jpg`）は**全部作り直しが要る**。WASD も「スペースでジャンプ」も実装にない
4. プレイヤーに出ている緑と黄色の線は**デバッグ描画が出しっぱなし**（`PogoPlayer.debug_draw` の既定が `true`）。
   `debug_draw` はどのシーンでも `false` にされていないので、本番のプレイ画面に出ている。
   palook さんの「傾いた際の線が気になりました」はおそらくこれ。
   消すか、**狙い表示として作り直すか**を決める必要がある

## 1. 実測値（この案の土台）

`godot --headless` で平地に `PogoPlayer` を置き、1バウンドごとの到達高さ・距離を測った。
`resources/pogo_stats_default.tres` の現在値（`pogo_authority = 0.4`）での結果。

計測に使ったスクリプトは `tools/measure_*.gd` に残してある。パラメータを変えたら
同じものを走らせれば測り直せる。

```
godot --headless --path . --script res://tools/measure_jump_height.gd
godot --headless --path . --script res://tools/measure_tilt.gd
godot --headless --path . --script res://tools/measure_stairs.gd
```

### 1バウンドごとの到達高さ（平地・真上）

| 状況 | 1回目 | 2回目 | 3回目 | 4回目 | 以降 |
|---|---|---|---|---|---|
| 何も押さない | 68px | 95px | 99px | 100px | **100px** |
| 溜め押しっぱなし（静止から） | 199px | 313px | 348px | 358px | **360px** |
| 溜め押しっぱなし（跳ねながら入る）※計算値 | 281px | 344px | 361px | 362px | **362px** |

- **何もしなくても 100px（0.4マス）は跳ねる。** 段差0.3マスまでは操作なしで越えられる
- **溜めっぱなしの到達点は 360px（1.44マス）。** ただしそこに届くのは4回目。1回目は 199〜281px しかない
- 引継ぎ資料の **282px は「跳ねている状態から1回だけ溜めた高さ」**。
  押しっぱなしを続ければ **360px まで伸びる**。資料にはこの区別が無かった
- 3行目は実測した1行目・2行目に合う式から出した計算値（1行目・2行目は計算と実測が1〜2%で一致）

### 落差を使ったとき（落ちてから溜めて跳ぶ）

| 落差 | 跳べる高さ |
|---|---|
| 250px | 330px |
| 500px | **394px** |
| 1000px | **496px** |
| 1500px | 584px |

引継ぎ資料の **568px は「約1400px の落差から溜めた高さ」**。普通に遊んでいて出る数字ではない。
実用域は **落差500pxで394px、落差1000pxで496px**。

> 落下死は `camera_bounds` の下端 +400px でしか起きない。プレイヤー側の `fall_threshold`(900px) は
> `game.gd` から繋がれていないので、**1000px 落ちても死なない**。落差は安心して使ってよい。

### 傾きと到達距離（平地・定常状態）

| 傾き | 溜めなし 高さ／水平 | 溜めあり 高さ／水平 |
|---|---|---|
| 0° | 100px ／ 0px | **360px ／ 0px** |
| 5° | 101px ／ 42px | 358px ／ 194px |
| 10° | 99px ／ 68px | 355px ／ 304px |
| 15° | 96px ／ 101px | 349px ／ 360px |
| 20° | 94px ／ 118px | 337px ／ 466px |
| 25° | — | 321px ／ 567px |
| 30° | — | 302px ／ 679px |
| 35°（最大） | 83px ／ 168px | **290px ／ 701px** |

- 傾けるほど横に伸び、そのぶん高さを失う。**登りと移動は同時には取れない**
- 溜めなしでは、最大まで傾けても **1バウンド168px（0.7マス）** しか進まない。
  溜めると **701px（2.8マス）**。4倍以上違う
- 1バウンドの周期は溜めありで **約2.85秒**（うち0.25秒は地面で踏みとどまっている時間）

### 他の実測・計算値

| | 値 | 設計への含意 |
|---|---|---|
| 画面に映る範囲 | **1371 × 771px**（1920×1080 ÷ zoom1.4） | **5.5 × 3.1マス**。1つの課題はこの枠に収める |
| 足場になる斜面 | **31.8°まで**（`ground_normal_threshold -0.85`） | 横10:縦6 より急だと壁。滑り落ちる |
| 溜めジャンプ1回の周期 | **2.85秒**（うち滞空2.6秒・地面0.25秒） | 「1バウンド」はこれだけ長い |
| 左右フル切り返し | **2.33秒**（70° ÷ 30°/秒） | 滞空2.6秒にちょうど収まる。**1バウンドで向きを1回変えられる**が設計の単位 |
| 中央へ戻る時間 | 1.4秒（35° ÷ 25°/秒） | 離してもすぐには戻らない |

## 2. 教える順番

全5ブロック。**1ブロック＝1画面（1371×771px）に収める**。
各ブロックの入口に復帰地点を置き、失敗してもそのブロックの頭からやり直せるようにする。

| # | 教えること | 越える壁 | 合格条件 |
|---|---|---|---|
| A | 跳ねるのは自動。A/Dは「傾き」 | 0.25マスの段差 | 傾けて3つの段を越える |
| B | **溜め押しっぱなしの連続ジャンプ** | 0.6マスの階段 | 押しっぱなしで登り切る |
| C | **同じ段で跳ね直して高さを溜める** | 1マスの段差 | 2〜3回跳ね直して登る |
| D | ためて、狙って、渡る（＋赤い床の初出） | 1.8マスの谷 | 溜め＋傾きで1バウンド |
| E | 落差は次の跳躍になる／滑る坂は乗れない | 1.6マスの棚 | 750px 落ちた勢いで跳び上がる |

A→B→C は「高さの作りかた」、D は「向きの作りかた」、E は「地形の読みかた」。
**新要素は1ブロック1つ**（仕様書 §11.2 の方針どおり）。

盛り込みたかった項目との対応:

| 盛り込む項目 | どこで |
|---|---|
| 基本操作 | A |
| ジャンプの練習 | A |
| ジャンプ押しっぱなしの連続ジャンプ | B |
| 溜めジャンプ | D（狙って1回ためる） |
| ジャンプ位置によるジャンプの結果の違い | C（同じ場所で跳ね直すほど高い）と E（落差のぶん高い） |

### この面で教えないこと

入れたくなるが、入れない。後の面の担当にする。

| | 理由 |
|---|---|
| 天井に当たると減速する（`ceiling_keep 0.2`） | 仕様書 §11.2 ではステージ3の担当 |
| 壁に沿って滑り落ちる（`wall_bounce_scale 0.39`） | 同じくステージ6の担当。**ブロックEの滑る坂で予告だけする** |
| 精密な溜め量の調整 | ステージ8の担当。チュートリアルでは「押しっぱなし」で済む作りにする |
| タイム短縮・ショートカット | 2周目以降の楽しみ。1周目で気づかせる必要はない |

## 3. ブロックごとの設計

1マス = 250px。開始地点の地面の上端を y=1000 とする。

### 全体の配置（目安）

実装した `scenes/stages/StageTutorial.tscn` の実寸。

| ブロック | 横 | 足場の上端 y | 中身 |
|---|---|---|---|
| A | -300 〜 1250 | 1000 → 820 | 60px の段を3つ（踏み面 120 / 170 / 540） |
| B | 1250 〜 3100 | 820 → 70 | 150px × 5段（踏み面 350） |
| C | 3100 〜 5200 | 70 → -680 | 250px × 3段（踏み面 700） |
| D | 5200 〜 6250 | -680 | 幅450px の谷（底は落下床） |
| E | 6250 〜 7400 | -680 → 70 → -330 | 750px 落下 → 400px の棚 |

- `camera_bounds` = **(-420, -1150, 7920, 2450)**。落下死線は y=1700
- 横7800px（31マス）は一本道だと長い。**C以降を左へ折り返す蛇行**にすれば
  半分程度に収まる。縦に積むほうが本作の見え方には合う（仕様書§10は縦6000pxまで確認済み）
- 復帰地点は **各ブロックの入口に1つずつ（計5つ）**。現行Stage01は3つなので増やす
- ⚠️ 復帰地点は **半径132px以内を通らないと記録されない**（`Game.checkpoint_radius`）。
  跳び越えていく軌道の真下に置くと取り逃す。**着地する足場の上に置くこと**

### A. 跳ねているだけ

```
看板A
  ┌──────┐                      ┌─┐
  │操作説明│            ┌─┐ ┌─┐ │ │   ← 60px の段を3つ
  └──────┘   ●        ─┘ └─┘ └─┘ └──
  ────────────────────────────────────  y=1000
  開始        ↑ 何も押さなくても 100px 跳ねている
```

- **最初の3秒で「ジャンプボタンは無い」を理解させる。** 開始位置は平地のまま。
  プレイヤーが何もしなくてもボールは跳ね続ける
- 段差は **60px（0.25マス）**。傾けながらでも 83〜96px は跳べるので、確実に越えられる。
  「傾けるだけで進める」が最初の成功体験になる
- 段の間隔を **120px → 170px → 300px** と広げる。
  無溜めの到達距離は傾き20°で118px、最大傾き35°で168px なので、
  1つ目は軽く傾けるだけ、2つ目は倒し切り、3つ目は2バウンドかかる。
  **「1回でどれだけ進めるか」の物差し**がここで入る
- 左端に壁を置き、左へ流れても落ちないようにする

**看板A の内容**（現 `Tutorial1.jpg` の差し替え）

```
    ほっといても跳ねます
    A / D （← →）  …… 傾く。傾いた向きへ跳ぶ
    SPACE            …… ためる（あとで使います）
    R                …… やり直し
    ［パッド］左スティック・十字キー左右 ／ A ／ セレクト
```

> palook さんの「R の表記が無い」をここで解消する。
> **WASD と「スペースでジャンプ」は消すこと**（W/S は入力マップに存在せず、SPACE はジャンプではない）。

### B. 押しっぱなしで登る

```
                                   ┌──┐ 計 750px
                            ┌──┐   │  │
                     ┌──┐   │  │   │  │   ← 150px ずつ／奥行き350px
              ┌──┐   │  │   │  │   │  │
       ┌──┐   │  │   │  │   │  │   │  │
  ─────┘  └───┘  └───┘  └───┘  └───┘  └──
  看板B
```

- 段差 **150px（0.6マス）／奥行き 350px** の階段を5〜6段。
  実測でこの組み合わせがいちばん素直に登れる（12段中10段まで連続登坂、§6）
- **無溜め（100px、傾けていれば83px）では1段も上がれない。**
  溜め押しっぱなしでないと進めない作りにする
- **奥行き350pxにする理由**: 溜め＋傾き15°の1バウンドが横360px。
  奥行きが足りないと段の壁（垂直面＝「壁」扱い）にぶつかって滑り落ちる。
  **段の奥行きは「そこで使ってほしい傾き角の水平距離」に合わせる**（§6の表）
- 段差を200pxにしたい場合は、奥行きを550pxまで広げること（実測で8段）。
  350pxのままだと200pxは2段で止まる
- 登り切った先は平らにして、一息つける場所にする

**看板B の内容**

```
    SPACE は押しっぱなし
    跳ぶたびに高くなります（4回目で最大）
    ［パッド］A 押しっぱなし
```

### C. 跳ね直して高さを溜める

```
                              ┌────┐ -200
                       ┌────┐ │    │
                ┌────┐ │    │ │    │   ← 250px（1マス）ずつ3段
         ┌────┐ │    │ │    │ │    │      踏み面は 700px と広め
    ─────┘    └─┘    └─┘    └─┘    └──
    看板C
```

- 段差を **250px（1マス）** に上げる。ここから**押しっぱなしのままでは登れなくなる**
  （1バウンドあたり約200pxが限界なので、登るほど勢いを失って頭打ちになる）
- 正解は **同じ段で2〜3回跳ね直してから次の段へ移る**。
  踏み面を 700px と広く取り、その場で跳ね直す余裕を作っておく
- **踏み面を狭くしてはいけない。** 400px で組んだところ、倒し切ったまま跳ぶと
  1バウンドで700px進んで次の段の壁に当たり、滑り落ちて永遠に進めなくなった
  （自動プレイで確認）。踏み面は**最大傾きの1バウンド（701px）以上**にして、
  倒しすぎても同じ段に戻ってこられるようにする
- **このブロックがチュートリアル全体の山**。八神さんが「攻略するうえで大切なテクニックだったので
  書いてあげても良いかなと」と書いていたのが、まさにこれ

**看板C の内容**

```
    1マスの段差は、一息に登れません
    同じ足場で 2〜3回 跳ね直してから登る
    ↑ 跳ねるほど高くなります
```

> ここは看板だけでなく、**段の横に「1・2・3」と跳ね直す回数を描いた地のグラフィック**を
> 置くと一目で伝わる。文字に頼らない説明をひとつ入れておきたい。

### D. ためて、狙って、渡る

```
    看板D
         ●                              ┌────────
    ─────┐                        ┌─────┘
         │   ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓    │        ← 赤い床（落下床）
         └───▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓────┘
              幅 450px（1.8マス）の谷
```

- 谷幅 **450px**。溜め＋傾き20〜25°（466〜567px/バウンド）で1バウンドで届く。
  無溜めでは最大まで傾けても168px/バウンドしか進まないので、絶対に届かない
- ⚠️ **復帰地点を谷の縁から500px以上離すこと。** 縁の100px手前に置いたところ、
  戻された直後に倒し切ってそのまま谷へ跳び込み、抜けられなくなった（自動プレイで確認）。
  **戻された地点から、助走に1〜2バウンドぶんの余裕を必ず取る**
- **谷底を赤い床（`Hazard`）にする。** 落下床の初出をここに置く意味:
  - 落ちても**すぐ手前の復帰地点**に戻るだけ（代償が最小）
  - 「赤＝触れたら落ちる」を、死んでも痛くない場所で一度体験させられる
- 八神さん・テスター3さんの両方が「赤い部分が分かりづらい」と書いている。
  現状の落下床は**テクスチャ無しの赤い単色ポリゴン**（`Hazard.fill_color = (0.62,0.16,0.19)`）で、
  テクスチャの貼られた地形の中に置くと「色違いの足場」に見える。
  **初出のここだけは、マグマなり剣山なり、触れたら痛いと分かる絵を必ず付ける**（§5参照）

**看板D の内容**

```
    SPACE でためる → 傾ける → 離すと跳ぶ
    ためている間も傾きは変えられます
    赤い床 ＝ 触れたら落下
```

### E. 落差は次の跳躍になる（最後の課題）

```
   看板E
  ──────┐ ← 飛び込み台（Dの出口）
        │
        │  750px 落ちる                ┌──── ゴール
        ▼                              │
                     ／＼ 滑る坂       │   ← 着地台から 400px
        ────────────／  ＼────────────┘
              着地台（ここで溜めたまま跳ねる）
                     ＼  失敗したら下へ抜けて、飛び込み台へ戻る
```

- **ゴール棚は着地台から 400px**。溜め押しっぱなしの上限は360pxなので、
  **その場で跳ねているだけでは絶対に届かない**。
  750px の落差を乗せて着地すれば約450px跳べるので、**落差を使うしか手がない**
  （飛び込み台から跳び出してから落ちれば実質1100px の落差になり、510px まで伸びる）
- **落ちている時間がそのまま「向きを作る時間」になる。** 750px をただ落ちるだけで1.8秒、
  飛び込み台から跳び出したぶんを足せば3秒以上ある。左右のフル切り返しが2.33秒なので、
  **落下中なら必ず向きを作り直せる**。
  「長い滞空の間に角度を作り込み、あとは委ねる」という本作の中核（仕様書§11.1）を、
  最後にもう一度やらせる
- **着地台の先は空けておく。** 勢いを使い損ねた場合、跳び出せずに詰むのではなく、
  下へ抜けて飛び込み台（復帰地点）へ戻る。**やり直しは5秒**。詰み状態を作らないこと
- 着地台の手前に **乗れる坂（25°）と滑る坂（40°）を並べて置く**。
  滑り落ちた先は着地台にして、滑っても死なないようにする
- 滑る坂は**見た目を明確に変える**（氷・濡れた金属・苔など）。
  テスター3さんの「はじめから滑るしかないなら滑るところは色を変えてほしい」、
  八神さんの「ツルツル床のような見た目のほうが分かりやすい」への直接の回答

> ⚠️ **ここは数字の余裕が薄い。** 「溜めっぱなしの上限360px」と「落差750pxで約450px」の間に
> 90px しか無い。棚の高さ400pxは必ず実機で詰めること。
> 余裕が欲しければ落差を1000pxに増やす（496px跳べる）。

**看板E の内容**

```
    高いところから落ちたぶん、次は高く跳べます
    落ちている間に、跳びたい向きへ傾けておく
    ツルツルの面には乗れません（滑り落ちます）
```

## 6. 設計に使う数表（レベルを置くときの早見）

### 段差を越えるのに要る技

| 段差 | 必要なもの |
|---|---|
| 〜60px (0.25マス) | 何も要らない（無入力で100px、傾けていても83px跳ねる） |
| 150〜200px (0.6〜0.8マス) | 溜め押しっぱなし。**連続して登り続けられる上限**（下の表） |
| 250px (1マス) | 溜め＋**同じ足場で2〜3回跳ね直し** |
| 〜360px (1.4マス) | 溜め押しっぱなしの最大（真上に跳んだとき） |
| 〜394px (1.6マス) | 500px の落差＋溜め |
| 〜496px (2マス) | 1000px の落差＋溜め |

> 横に動きながら登れる高さは、真上に跳ぶときの約8割（最大傾きで290px）。
> **登りと移動は同時に取れない。**

### 階段を連続で登れる限界（実測）

12段の階段を置き、溜め押しっぱなし＋傾きっぱなしで45秒登らせた結果。

| 傾き | 段の奥行き | 段差 | 登れた高さ | 段数 |
|---|---|---|---|---|
| 15° | 350px | **150px** | **1532px** | 10段 |
| 15° | 350px | 200px | 545px | 2段 |
| 15° | 350px | 250px | 595px | 2段 |
| 25° | 550px | **150px** | **1361px** | 9段 |
| 25° | 550px | **200px** | **1697px** | 8段 |
| 25° | 550px | 250px | 322px | 1段 |

- **1マス（250px）の階段は、どの条件でも数段で頭打ちになり登り切れなかった。**
  段を1つ登るごとに着地速度が落ち、跳べる高さがどんどん下がるため
- 連続して登れるのは **1バウンドあたり 150〜200px（0.6〜0.8マス）**
- **奥行きが効く。** 200px の段差は奥行き550px（傾き25°）だと8段登れたが、
  奥行き350px（傾き15°）では2段で止まった。
  奥行きが足りないと段の壁（＝垂直面なので「壁」扱い）にぶつかって滑り落ちる
- 結果は段差に対して一直線ではない（15°/300px が 945px 登るなど）。
  段のどこに着地するかで次が変わるので、**最終的な段差は必ず実機で詰めること**

| | 使える組み合わせ |
|---|---|
| 押しっぱなしのまま登らせたい | **段差150px・奥行き350px**（いちばん素直）／段差200px・奥行き550px |
| 跳ね直しを強制したい | **段差250px（1マス）以上** |

### 置くときに守ること（自動プレイで分かったこと）

実際に組んで `tools/playtest_tutorial.gd` で走らせたときに踏んだ罠。

| | 守ること | 守らないと |
|---|---|---|
| 段の踏み面 | **最大傾きの1バウンド（701px）以上**か、倒しすぎても同じ段に戻れる形にする | 倒し切ったまま跳ぶと次の段の壁（垂直面＝壁扱い）に当たって滑り落ち、永遠に進めない |
| 復帰地点と崖の縁 | **500px 以上離す**（助走1〜2バウンドぶん） | 戻された直後に倒し切って、そのまま谷へ跳び込む |
| 足場の幅 | **1バウンドの水平距離以上** | 乗った次の瞬間に跳び越してしまう |

### 谷を渡るのに要る技

| 谷幅 | 必要なもの |
|---|---|
| 〜168px (0.7マス) | 無溜め・最大傾き |
| 〜360px (1.4マス) | 溜め・傾き15°（高さも349px残る） |
| 〜701px (2.8マス) | 溜め・最大傾き（高さは290pxまで落ちる） |

### 斜面

| 角度 | 挙動 |
|---|---|
| 〜31.8° | 足場。跳ね返れる |
| 31.8°〜 | 壁。`wall_bounce_scale 0.39` まで減速して滑り落ちる |

坂を置くときは **横10に対して縦6まで**。1マス（250px）上げる坂には、
最低でも横403px（1.6マス）の助走幅が要る。

### 傾き角ごとの1バウンド

§1 の表を参照。置くときの目安だけ再掲すると:

- **真上に高く**跳ばせたいところ … 傾き0〜10°で 355〜360px
- **登りながら進ませたい**ところ … 傾き15°で 高さ349px・横360px（1画面に収まる扱いやすい単位）
- **渡らせたい**ところ … 傾き30〜35°で 横679〜701px、ただし高さは290〜302pxまで落ちる

### 自動プレイの結果（2回目・現在のシーン）

| ブロック | 結果 | 内容 |
|---|---|---|
| A 傾けて段を越える | **ok** | 13.3秒・12バウンドで到達 |
| B 押しっぱなしで登る | **ok** | 20.9秒・9バウンドで到達 |
| C 跳ね直して登る | **NG** | x=3786 で停止。段の根元まで流れ、垂直の壁に当たり続けて抜けられない |
| D 谷を渡る | **NG** | 復帰地点(4700)から倒し切って跳ぶと、谷(5200〜5650)の中に落ちる |

4. **着地台(E_Landing)には復帰地点を置かないこと。** あそこで戻されると落差を失い、

## 10. 実装（1ステージ6区画の作りに変更）

「1本道のチュートリアル面を通して遊ぶ」から、**1つのステージを 3x2 に割って
1区画＝1チュートリアル**に作り替えた。区画ごとに開始位置・判定アイテム・
メッセージを持ち、区画の終わりで「もう一度やる / 次へ進む」を選ばせる。

### 10.1 区画の割り当て

`CameraBounds`（ステージ全体 = 7500 x 3000）を横3 × 縦2に等分し、
`Tutorials` の下の並び順どおりに割り当てる。1区画は **2500 x 1500**。

```
┌──────────┬──────────┬──────────┐
│ 1 基本操作 │ 2 ジャンプ │ 3 押しっぱ │   y 0..1500
│          │  の練習   │  なし連続  │
├──────────┼──────────┼──────────┤
│ 4 溜め    │ 5 跳ぶ場所 │ 6 総合    │   y 1500..3000
│  ジャンプ  │  で変わる  │ →本編へ   │
└──────────┴──────────┴──────────┘
  x 0..2500   2500..5000  5000..7500
```

区画の範囲は**カメラの可動範囲と落下死の線を兼ねる**。区画ごとに持つので、
隣の区画が画面に入り込んだり、落ちたときに隣へ落ちていったりしない。
1区画だけ広く取りたいときは、その区画に `Bounds`（Polygon2D）を置けば優先される。

区画の共通寸法（区画ローカル座標、左上が 0,0）:

| もの | 位置 |
|---|---|
| 左右の壁 | x 0..80 と 2420..2500、y 150..1300 |
| 主な足場の上面 | y 1150 |
| 落下床（赤・触れたら死） | y 1380..1480、幅いっぱい |

落下死は `camera_bounds` 由来の線ではなく**区画の中に置いた落下床**で起こす。
線に頼ると、上の段の区画から落ちたときに下の段の地形に乗ってしまう。

### 10.2 ノードの構成

```
StageTutorial  (TutorialStage ← Stage を継承)
├── CameraBounds (Polygon2D)      ステージ全体。これを 3x2 に割る
├── Spawn (Marker2D)              保険。区画が無いときだけ使う
└── Tutorials (Node2D)
    ├── Tutorial1 (TutorialSection)
    │   ├── Spawn (Marker2D)      ← この区画の開始位置
    │   ├── Item (TutorialItem)   ← クリア判定アイテム
    │   ├── RecoveryPoints/Point1..
    │   ├── Terrain (StaticBody2D) / CollisionPolygon2D(TerrainPolygon)...
    │   ├── Hazards (Hazard) / Pit
    │   └── Signs / Sign (Label)  ← 看板は仮。Label のまま
    └── ... Tutorial6
```

- **`TutorialStage`** は `Stage` の問い合わせ（`get_spawn_position`
  `get_recovery_points` `camera_bounds`）を「今の区画のもの」に差し替える。
  そのため `Game` 側のカメラ制限・落下判定・復帰処理は今までの呼び出しのまま動く。
- **`TutorialSection`** は区画1本ぶん。`title` / `hint`（画面上に出す操作説明）/
  `message`（クリア時の文章）を持つ。
- **`TutorialItem`** は区画の合格判定。`Goal` とは別物にしてある（Goal はタイム送信・
  ランキング・記憶コレクションに繋がるが、こちらは何も記録しない）。絵が無ければ
  仮の丸を自分で描くので、絵の前にレベルデザインを進められる。
  有効なのは今の区画のものだけで、他は薄く表示されるが判定しない。
- **`TutorialHint`** は画面上部の説明を切り替える範囲。区画の中に置いて、
  プレイヤーがその範囲に居る間だけその文章が出る。詳しくは §10.8。
- **`TutorialUI`** は画面上の操作説明と下のメッセージボックス。
  メッセージ中にボタン（SPACE / Enter / Aボタン）を押すと
  「もう一度やる / 次へ進む」が出る。選択は **A D**（遊んでいるときの傾けるキー）と
  矢印キー・スティックの両方で動かせる。持ち替えずに選べるようにするため。ツリーは止めない（触れた時点で
  プレイヤーを止めるので進まない）ため、クリアのモーションはそのまま動く。

### 10.3 進行

```
タイトル TUTORIAL
  → Game._ready が SaveGame.tutorial_requested を見て load_tutorial()
  → 区画1を有効化して開始
  → アイテムに触れる → メッセージ → [もう一度やる] → 同じ区画をやり直し

```

`stages` にも入れていないので、ステージ番号・`stage01`〜`stage10` の
リーダーボード・10個の記憶は一切動かない。

### 10.8 場所で切り替わる説明（TutorialHint）

画面上部の説明は、区画ごとに1つではなく**プレイヤーの居る場所で切り替わる**。

```
Tutorial4 (TutorialSection)
├── hint = "同じ場所で2〜3回跳ね直すと高さが戻る …"   ← 既定。どの範囲にも居ないとき
└── Hints (Node2D)
    ├── Hint1  x 450..900    "ここで2〜3回跳ね直して高さを作り、それから右へ傾ける"
    ├── Hint2  x 900..1550   "もう一段ある   同じように跳ね直してから"
    └── Hint3  x 1550..2500  "登れた   玉へ"
```

`TutorialHint` は位置とサイズを持つ `Node2D`。Area2D ではなく**毎フレームの位置の
比較**で決めている。

- 当たり判定を増やさない。説明を出すために物理に仕事をさせたくない
- 「入った / 出た」の通知順に左右されない。落下復帰やデバッグワープで
  飛んでも、次のフレームには必ず正しい文章になる

範囲が重なっているときは `priority` の大きいほうが勝ち、同じなら**狭いほう**が勝つ。
「広い範囲でざっくり説明し、その中の狭い範囲だけ別の説明にする」が書けるようにしている。

枠はエディタでだけ描かれる（遊んでいるときは見えない）ので、
エディタで `Hint1` を選んでドラッグすれば切り替わる場所を直せる。
座標から作り直すなら `tools/gen_tutorial_stage.py` の各区画の `"hints"`。
形式は `((x0, y0, x1, y1), "文章")` で、座標は区画のローカル。

`tools/check_tutorial_stage.gd` が次の3点を見る。

- 範囲が区画の外へはみ出していないか
- 文章が空でないか
- **その範囲の中心でも別の文章が勝ってしまわないか**（他の範囲に覆われていて、
  置いたのに一度も出ない状態を拾う）

`tools/check_tutorial_flow.gd` は実際にプレイヤーを各範囲へ飛ばして、
画面に出ている文章が切り替わること・範囲から出れば既定へ戻ることを見る。

### 10.9 背景（マトリックス風の文字の雨）

チュートリアル面だけ、本編と違う背景を出す。緑の文字が降るスクリーンシェーダー。

```
StageTutorial (hide_world_background = true)
└── MatrixBg (CanvasLayer, layer = -100)
    └── Rain (ColorRect 全画面, matrix_rain.gdshader, matrix_parallax.gd)
```

| ファイル | |
| --- | --- |
| `resources/shader/matrix_rain.gdshader` | 本体（奥の雨・漂う大文字・手前の雨の3層） |
| `resources/texture/matrix_glyphs.png` | 文字アトラス 16×6＝96文字 |
| `scripts/matrix_parallax.gd` | 視差。カメラ（とマウス）に合わせて各層をずらす |
| `tools/make_glyph_atlas.py` | アトラスを作り直す |

**共通背景を隠す仕組み。** `Main` の `Background` は全ステージ共通で、2Dの世界
（layer 0）に置かれている。負の層の CanvasLayer はその奥に描かれるので、出した
ままだと雨が隠れてしまう。そこで `Stage.hide_world_background` を立てた面では
`Game._apply_world_background()` が共通背景を隠す。面を抜ければ元に戻る。

**文字を変える。** `tools/make_glyph_atlas.py` の `GLYPHS` を書き換えて実行する。
今はカタカナ46＋数字10＋漢字40（『泥酔配信者異世界転生記憶大好物』など作品の字）。
数を変えるならシェーダーの `atlas_grid` と `glyph_count` も合わせること。
フォントは Noto Sans JP（OFL）。配布できないフォントは使わない。

```
python tools/make_glyph_atlas.py
```

**濃さを変える。** `StageTutorial.tscn` の `Rain` の材質（ShaderMaterial）。
遊ぶ画面の後ろなので、既定値より暗く・薄くしてある。

| 値 | 今 | |
| --- | --- | --- |
| `bg_color` | (0, 0.1046, 0) | 何も降っていないところの色。画面では rgb(0, 20, 0) |
| `brightness` | 0.75 | 全体の明るさ |
| `density` | 1.0 | 降る列の割合。1.0 で全部の列が降る |
| `rain_rows` | 42 | 縦の枡数（大きいほど枡が細かい） |
| `glyph_fill` | 0.98 | 枡の中で文字が占める割合。1.0 で隙間なし |
| `trail_length` | 42 | 尾の長さ（枡の数）。`rain_rows` と同じ＝画面の高さぶん |
| `float_alpha` | 0.22 | 漂う大文字の濃さ |

**カメラに連動してずれる。** 背景は画面に貼り付いた CanvasLayer なので、
放っておくとカメラが動いても止まって見える。`follow_camera` を入れると、
カメラが `camera_span` だけ動くごとに視差が1つぶん動く。向きはカメラと逆で、
**右へ進むと背景は左へ流れる**（同じ向きに流したいときは `camera_span` を負に）。
絶対位置で決めているので、同じ場所へ戻れば背景も同じところへ戻る。

**文字の大きさと隙間は別々に決まる。**

```
画面に出る文字の大きさ ≒ (1 / rain_rows) × glyph_fill × アトラスの字面
文字と文字の隙間       ≒ (1 / rain_rows) × (1 - glyph_fill × アトラスの字面)
```

隙間を詰めたいなら `glyph_fill` を上げる。そのぶん文字が大きくなるので、
**大きさを保つなら `rain_rows` も一緒に上げて枡を細かくする**。今の値は
30 / 0.82 から 42 / 0.98 へ動かしたもので、文字の大きさはほぼ同じまま
隙間だけがおよそ 1/4 になっている。`trail_length` は枡の数で数えるので、
`rain_rows` を変えたら同じだけ動かすこと。

アトラス側の余白も詰めてある（`make_glyph_atlas.py` の `FONT_SIZE = 90`、
枡96pxに対して縁に `MARGIN = 2` px だけ残す）。これ以上大きくすると隣の枡の字が
にじんで出るので、生成時にはみ出しを見張っている。

雨そのものを濃くしたいときは `density` と `trail_length`。

**色は最後に `brightness` が掛かる。** `bg_color` を rgb(0, 20, 0) に見せたいなら
`20 / 255 / brightness` を入れる（今は 0.1046）。`brightness` を動かしたら
地の色も一緒にずれるので、合わせ直すこと。

| 値 | 今 | |
| --- | --- | --- |
| `follow_camera` | true | カメラ連動 |
| `camera_span` | 1000 | カメラがこれだけ動くと視差1つぶん (px) |
| `mouse_weight` | 0.15 | マウスの効き。添える程度 |
| `key_speed` | 0 | 矢印キーの流れは切ってある（傾ける操作とぶつかるため） |

奥の層ほどずれが小さく（`depth` 0.4）、漂う大文字がいちばん大きくずれる（1.6）。

背景の上に本編と同じ `CameraBounds` の橙色を重ねると全体が濁るので、
チュートリアル面ではその枠を `visible = false` にしてある（エディタで選べば
頂点は編集できる）。

**見た目の確認。**

```
godot --path . --script res://tools/shot_tutorial.gd -- out.png 3.0 0
```

区画番号（0〜5）のあとに、右へずらす量(px)も渡せる。
`tools/check_tutorial_flow.gd` も、チュートリアル中に共通背景が隠れていること・
右へ進むと背景が**左へ**流れること・本編で共通背景が戻ることを見ている。

### 10.11 地形の見た目（縁が光る板）

`resources/shader/neon_block.gdshader`。面は上から下へ暗くなるグラデーション、
縁は白に寄せて光らせる。薄い格子も入る。背景の文字の雨と揃えた見た目。

板の色は頂点カラー（`TerrainPolygon.fill_color`）から取る。シェーダーは
明るさを掛けて縁を白に寄せるだけなので、1本のシェーダーで色違いが出せる。

| | 色 | |
| --- | --- | --- |
| 足場 | `Color(0.16, 1, 0.45)` | 緑 |
| 滑る坂 | `Color(0.25, 0.72, 1)` | 青。この板だけ氷のシェーダー（10.12） |
| 区画の左右の壁 | `Color(0.13, 0.58, 0.55)` | 奥に引くので地味に |
| 落下床 | `Color(1, 0.25, 0.3)` | 赤。この板だけ熱のシェーダー（10.13） |

#### 形をどう渡しているか

縁からの距離が要るので、板の形をシェーダーへ渡す。

| 値 | |
| --- | --- |
| `edges` | 1本の辺につき `Vector3(内向きの法線.x, .y, 原点からの距離)` |
| `edge_count` | 辺の本数（最大16） |
| `bounds` | 外接矩形 `Vector4(左, 上, 幅, 高さ)`。縦のグラデーションに使う |

シェーダー側は `dot(法線, 位置) - 距離` で「その辺までの距離(px)」を出し、
一番近い辺までの距離を縁からの深さとして使う。位置は頂点シェーダーの
`VERTEX`（ポリゴンのローカル座標）をそのまま読む。
`terrain_fill.gdshader` が `bottom_y` でやっているのと同じ考え方。

距離は px で見ているので、**板の大きさが変わっても縁の太さは変わらない**。
坂のような斜めの辺でも、辺に沿って正しく光る（外接矩形ではなく実際の辺を見ている）。

#### マテリアルは板1枚に1つ

`edges` が板ごとに違うので、マテリアルは共有できない。
`tools/gen_tutorial_stage.py` が形から計算して、`.tscn` に板の数だけ
`[sub_resource type="ShaderMaterial"]` を書き出す。
**レベルデザインを変えたら、必ず生成し直すこと**（手で座標だけ直すと縁がズレる）。

```
python tools/gen_tutorial_stage.py
```

#### 見た目を変えたいとき

`neon_block.gdshader` の uniform の既定値を直す。全部の板に効く。

| uniform | 既定 | |
| --- | --- | --- |
| `line_width` | 3 | はっきり光る線の太さ (px) |
| `line_white` | 0.6 | 線をどれだけ白に寄せるか |
| `glow_width` | 28 | 線から内側へ流れる光の幅 (px) |
| `glow_strength` | 0.45 | その光の強さ |
| `face_top` / `face_bottom` | 0.40 / 0.05 | 面の明るさ。差がグラデーションになる |
| `grid_size` / `grid_width` / `grid_strength` | 120 / 2 / 0.13 | 面に薄く入れる格子 |

### 10.12 滑る坂の見た目（氷の板）

`resources/shader/ice_block.gdshader`。登れずに滑り落ちる急坂だけ、
縁が光る板ではなく氷にする。**足場にならないことを色だけでなく質感でも見せる**のが目的。

形の渡し方（`edges` / `edge_count` / `bounds`）と `VERTEX` の読み方は
`neon_block.gdshader` と同じなので、生成スクリプトは書き出す値を変えずに
シェーダーの指定先だけ差し替えている。色も同じく `fill_color` から取る。

中身の違いは3つ。

- 面をボロノイで**結晶の粒に割り**、粒ごとに明暗をつける
- 粒の**割れ目を白く光らせる**
- 表面を**ゆっくり光が流れる**（`sheen_speed` を 0 にすれば止まる）

#### 板を氷にする書き方

`SECTIONS` の `terrain` は `(名前, 形, 色)` だが、4つ目に `ICE` を足すとその板だけ氷になる。
書かなければ今まで通り `NEON`。

```python
("RampSlip", [(1500, FLOOR_TOP), (1650, 1024), (1650, FLOOR_TOP)], BLUE, ICE),
```

#### 見た目を変えたいとき

| uniform | 既定 | |
| --- | --- | --- |
| `shard_size` | 38 | 結晶の粒の大きさ (px) |
| `shard_stretch` | 0.6 | 1より小さいと粒が縦に伸びる |
| `shard_contrast` | 0.34 | 粒ごとの明暗の差 |
| `crack_width` / `crack_light` | 2 / 0.62 | 割れ目の太さ (px) と白さ |
| `white_mix` | 0.38 | 素の色を白へ寄せる量。氷の薄さ |
| `face_top` / `face_bottom` | 0.9 / 0.42 | 面の明るさ。差がグラデーションになる |
| `line_width` / `line_white` | 2.5 / 0.9 | 縁の線の太さと白さ |
| `glow_width` / `glow_strength` | 16 / 0.5 | 縁から内側へ流れる光 |
| `sheen_speed` / `sheen_width` / `sheen_strength` | 0.35 / 0.0075 / 0.18 | 表面を流れる光 |

### 10.13 落下床の見た目（熱い板）

`resources/shader/lava_block.gdshader`。落ちたら死ぬ床（`Hazards/Pit`）に貼る。
形の渡し方は 10.11・10.12 と同じで、中身だけが違う。

冷えた殻（暗い）を熱の筋（明るい）が割っている絵にして、筋はゆっくり流れる。
**上の面を一番熱く**しているのは、そこがプレイヤーの触れる面で、
どこから下が危ないかを一目で見せたいから。熱いところだけ陽炎で揺らぐ。

色は `fill_color` から取り、熱いところだけ `hot_color`（既定は橙寄りの黄）へ寄せる。

> `Hazard` は `_ready` で子の `TerrainPolygon` の色を自分の `fill_color` で
> 上書きする。そのため生成スクリプトは `Hazards` ノード側にも色を書いている。
> ここを書き忘れると、Pit に指定した色ではなく `Hazard` の既定の暗い赤になる。

#### 本編ステージの落下床にも貼ってある

本編は手書きの `.tscn` なので、別のスクリプトで貼る。何度流しても結果は同じ。

```
python tools/apply_hazard_material.py
```

| ステージ | 落下床 | |
| --- | --- | --- |
| Stage02 | 1枚（1600x120） | 全部見える |

スクリプトはマテリアルを足す前に、**ノードの `scale` をポリゴンの座標に畳み込む**。

#### チュートリアルでは今は画面に映らない

ただし `camera_bottom_trim` は「カメラがプレイヤーの上下動を追いすぎて
地面のほうが跳ねて見える」のを止めるために入れたものなので、下げるなら 10.x の

### 10.14 本編ステージの滑る面の線（青いライン）

`scripts/terrain_sprite.gd`。跳ね返せない角度の面に、踏む前から
「ここは滑る」と分かる青い線を引く。色はチュートリアルの氷の板（10.12）と揃えてある。

引く場所は毎回形から計算するので、**`.tscn` には何も書いていない**。
`Outline` と同じやり方で、`SlipMarks` の下に `Line2D` を自動で作る（owner を
付けないので保存されない）。地形の形を直せば、線もその場で引き直る。

#### どの辺に引くか

角度をコードに書いてはいけない。**`PogoStats.ground_normal_threshold` から毎回読む**
（既定の `resources/pogo_stats_default.tres` では -0.85 = **31.79度までは跳ねる**）。
書き写してしまうと、あとで跳ね返しの境目を変えたときに線だけが嘘になる。

辺の条件は3つ。

1. 上を向いている（下向きの面は踏めないので関係ない）
2. `ground_normal_threshold` より急（これより緩ければ跳ねる）
3. `slip_max_angle`（既定 80度）より立っていない。
   真横に近い面は見ただけで壁だと分かるので、引いても賠やかになるだけ

形は見た目のポリゴンではなく、**`copy_from` のコリジョンから取る**。
見た目は裾を下に伸ばしたりしているので（`Gfx_Block00` は左右と下に広い）、
そこから取ると実際には滑らない辺に線が出てしまう。

角度は**ワールド座標で**見る。`Gfx_Block02` の `scale(1.64, 1)` のように
縦横別に拡大されたブロックが多く、ローカルの傾きと実際に当たる傾きが違うため。
線自体も `SlipMarks` で親の変形を打ち消してから引くので、太さがブロックごとに変わらない。

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 本数 | 4 | 6 | 0 | 0 | 0 | 0 | 15 | 21 | 6 | 8 |

Stage03〜06 が 0 なのは、あの辺りの足場が横長の箱ばかりで、滑る角度の面が無いから。

#### 見た目を変えたいとき

`Graphics` の各 `Gfx_*`（TerrainSprite）のインスペクタ、「滑る面」の群。

| --- | --- | --- |

### 10.15 本編ステージの地面の模様（パララックス）

`resources/shader/terrain_pattern.gdshader` と `scripts/terrain_sprite.gd`。
地面を1枚の絵で敷き詰め、カメラの移動に合わせて模様だけを少し遅れて動かす。

#### 入れかた（ドラッグするだけ）

1. ステージを開き、地形の `Gfx_…` ノードを選ぶ（Shift で複数選べる）
2. インスペクタの「模様」グループにある **`ground_pattern`** 欄へ、
   ファイルシステムから **`resources/ground_pattern_grass.tres`** をドラッグする

これだけで、そのブロックは模様で塗られ、パララックスも入る。ノードの
テクスチャを差し替えたり、チェックを入れたりする必要はない。
欄を空にすると、元のテクスチャの塗りにそのまま戻る（.tres の絵は
ノードのテクスチャとは別にシェーダーへ渡しているので、ノード側は何も書き換えない）。

`ground_pattern_grass.tres`（`GroundPattern`）が持っている値。開いて直すと、
**この .tres を割り当てた全ブロックがその場で変わる**。

| | 既定 | |
| --- | --- | --- |
| `texture` | `ground_grass_pixel.png` | 模様の絵 |
| `size` | (1024, 1024) | 絵1枚ぶんの大きさ（ワールド px） |
| `mirror_tiling` | off | 1枚ごとに反転。四辺が繋がっていない絵で入れる |
| `parallax_strength` | 0.06 | カメラが 100px 動くと模様が 6px ずれる。0 で動かない |
| `parallax_smoothing` | 3.0 | 追いつく速さ |

別の柄も使いたいときは、.tres を複製して `texture` を替え、そちらを割り当てる。
`.tres` を割り当てているあいだ、ノード側の `pattern_*` / `parallax_*` /
`mirror_tiling` は見ない（インスペクタには残るが効かない）。
枠線の `outline_look`（10.16）と同じ作り。

#### これまでの塗り（`terrain_fill`）との違い

| | `terrain_fill` | `terrain_pattern` |
| --- | --- | --- |
| UV | Polygon2D の UV（`tile_size`） | **ワールドの px**（`pattern_size`） |
| ブロックをまたぐと | ブロックごとに貼り直し | **柄が繋がる** |
| ノードの拡大率 | 模様が伸びる | 影響しない |
| カメラ | 動かない | `parallax_offset` のぶん動く |

本編の Gfx ブロックは縦横別に拡大されているものが多い（Stage04 の `(0.28, 2.6)` など）。
UV のまま貼るとブロックごとに模様の伸び方が変わるので、ワールド座標で敷いている。
影（下端を暗くする）は `terrain_fill` と同じものを持っていて、見え方は変わらない。

#### ノード側のつまみ（TerrainSprite。.tres を使わないとき）

ブロック1枚だけ値を変えたいときは、`ground_pattern` を空にしてこちらを使う。

| | 既定 | |
| --- | --- | --- |
| `pattern_enabled` | off | 入れると `terrain_pattern` に替わる。外すと `terrain_fill` に戻る |
| `pattern_size` | (1024, 1024) | 模様1枚ぶんの大きさ（ワールド px） |
| `parallax_strength` | 0.06 | カメラが 100px 動くと模様が 6px ずれる。0 で動かない |
| `parallax_smoothing` | 3.0 | 追いつく速さ。カメラの上下の揺れを拾わないよう鈍らせてある |
| `mirror_tiling` | off | 1マスごとに絵を反転。四辺が繋がっていない絵で使う |

手で氷や熱い板のマテリアルを貼ってあるノードは触らない。入れ替えるのは
`terrain_fill` と `terrain_pattern` の2本だけ。

#### ドットを大きく見せる（ピクセルアート風）

ドットの大きさは2つで決まる。**絵のドット数**と、**何pxで見せるか**（`pattern_size`）。

```
ワールドでの1ドット = pattern_size ÷ 絵のドット数
```

貼っている絵は 128px、`pattern_size` は 1024 なので、1ドットはワールド 8px。
カメラの zoom が 1.4 なので、画面では約 11px の四角になる。

| 絵 | `pattern_size` | 1ドット | 画面では | |
| --- | --- | --- | --- | --- |
| 512px | 256 | ワールド 0.5px | 0.7px | 縮小されてドットが潰れる |
| 512px | 1024 | 2px | 2.8px | |
| **128px** | **1024** | **8px** | **11px** | 今これ |

**柄の大きさを変えずにドットだけ粗くしたいときは、絵のドット数を減らす**
（`tools/pixelate.py`）。`pattern_size` を上げると、ドットと一緒に柄も大きくなり、
繰り返しの間隔も伸びる。どちらもドットは大きくなるが、見え方は別物になる。

**ぼかしは入らない（最近傍で固定）。** `terrain_pattern` は絵を `texture()` ではなく
`texelFetch()` で1ドットずつ直接読む。`texture()` だとフィルタがノードの
`texture_filter` に従うので、ノードを Linear にしたり、このマテリアルを別のノードに
貼ったりするとドットの境目がぼける。`texelFetch()` はフィルタを通らないので、
どこに貼っても四角いドットのまま出る。

確かめかた: 画面に出ている色が全部「絵にある色そのもの」なら、混ぜた色（ぼかし）は無い。

| | 絵にある色の割合 | 1px だけの並び |
| --- | --- | --- |
| 対照: 素の Polygon2D を Linear にした | 49.7% | 78.5% |
| 模様 + ノードは Nearest | 100% | 0.8% |
| 模様 + ノードを Linear にした | **100%** | 0.0% |
| 本番のステージ1（地面） | **100%** | 0.0% |

ほかにぼけの元になるものも無い。プロジェクトの既定フィルタは Nearest
（`default_texture_filter=0`）、絵の取り込みはミップマップ無し・非圧縮、
本編10面の Gfx ノードは全部 `texture_filter = 1`（Nearest）。

#### 色が絵より濃くなっていた件（直した）

`terrain_fill` と `terrain_pattern` は、絵を**2回掛けて**いた。

```glsl
vec4 tex_color = texture(TEXTURE, uv) * COLOR;   // 直す前
```

fragment に入ってくる `COLOR` には、組み込みが**もう `texture(TEXTURE, UV)` を掛けてある**
（頂点の色 × 絵）。そこへ自分で読んだ絵をさらに掛けると、絵が2重になる。

- UV が同じなら色が2乗になる。暗い成分ほど強く沈むので、**暗く・濃く**見える
  （tile_00 のクッキーで 219,138,75 → 194,81,23）
- UV が違うと（反転タイリング、`terrain_pattern` のワールド座標）、
  **別の写像の絵が薄く重なる**。模様の上に Polygon2D の UV で貼った絵がもう1枚乗っていた

直しかたは、頂点の色を `vertex()` で取っておいて、そちらを掛けること。

```glsl
varying vec4 vertex_color;
void vertex() { vertex_color = COLOR; }
...
vec4 tex_color = texture(TEXTURE, uv) * vertex_color;   // 直したあと
```

同じ絵を描きかた別に並べて測った値（平均）:

| | 色 |
| --- | --- |
| tile_00.png そのもの | 219.4, 138.5, 75.0 |
| 素の Polygon2D | 219.3, 138.5, 75.1 |
| `terrain_fill`（直す前） | 194.2, 81.1, 22.8 |
| `terrain_fill` / 反転あり | 219.3, 138.5, 75.1 |
| `terrain_pattern` / 反転あり | 219.3, 138.5, 75.1 |

はじめは「シェーダーを通すと2乗される」と見て平方根で戻していたが、それは
UV が同じときにたまたま合うだけだった（反転や模様では2枚の絵が混ざったまま）。
原因を直したので平方根は外した。

neon / ice / lava は絵を読まず頂点の色だけで描くので、この問題は無い
（`COLOR` = 頂点の色 × 白）。`event_bg_hide.gdshader` は前からこの点に気づいていて、
末尾に「COLOR を掛けてはいけない」と書いてある。

**`raster_scroll.gdshader`（背景の揺れ）も同じ書きかたをしていたので、同じように直した。**
`Background.tscn` の `Far`（bg_c_01.png）で使っている。揺らしている背景が濃く出て、
揺れていない絵が薄く重なっていた。

| bg_c_01.png | 平均の色 |
| --- | --- |
| 素の Sprite2D | 43.1, 60.1, 71.3 |
| raster（揺れ 0） | 43.1, 60.1, 71.3 |
| raster（揺れ 3、本番の値） | 43.1, 60.1, 71.3 |
| 素 + 色味（modulate） | 33.3, 52.3, 71.3 |
| raster + 色味（modulate） | 33.3, 52.3, 71.3 |

`bg_layer.gd` は `tint` を modulate で掛けているが、modulate は頂点の色に入って
くるので、直したあとも今までどおり効く。

自分でシェーダーを書くときは、**`texture(TEXTURE, …)` を読んだら `COLOR` ではなく
`vertex()` で取っておいた頂点の色を掛ける**。絵を読まないシェーダー（neon / ice / lava / 雪）は
`COLOR` をそのまま使ってよい。

#### パララックスの入れかた

`TerrainSprite` が自分で入れる。模様が入っていて（`ground_pattern` があるか
`pattern_enabled`）、強さが 0 より大きいときだけ、ゲーム中も `_process` を回して
カメラの見ている場所（`get_screen_center_position`）× `parallax_strength` を
`parallax_offset` に渡す。

**見ている場所そのものを基準にする**のが要。足した量で動かすと、行ったり来たり
しているうちに模様が流れていき、同じ場所に戻っても柄が合わなくなる。

**最初の1枚から合わせる。** `_process` が回り始めるのはノードが入った次のフレーム
からなので、以前は読み込み直後の2フレームが「ずれ 0」で描かれ、3フレーム目に
模様が 30〜40px 跳んでいた（ゲーム開始直後に1回ずれて見えた件）。今は `_ready` から
遅延呼び出しで、描画の前にその場の値へ合わせている。遅延にしているのは、ステージを
読み込んだあとに `game.gd` がカメラの範囲を設定してカメラを動かすため。

**瞬間移動では追いかけない。** カメラが1フレームで 300px 以上動いたとき
（落下からの復帰、カメラ範囲の付け直し）は、ゆっくり追わずにその場へ合わせる。
追いかけると、復帰のたびに模様が1秒ほどかけて滑っていく。

#### まとめて貼る

```
python tools/apply_ground_pattern.py [--all] [Stage01 Stage02 ...]
```

ステージ名を書かなければ本編10面すべて。`Gfx_` のあとが
Ground / Ramp / Platform / Floor / Slope / Block のノードだけに貼り、
壁や天井（Wall / Ceiling）はそのままにする。`--all` で Gfx_* 全部に貼る。
やっているのは、各ノードの `ground_pattern` に `ground_pattern_grass.tres` を
割り当てること（ドラッグと同じ）。前の版で書いた `pattern_enabled` などの行は消す。
**そのステージをエディタで開いていないときに流すこと**（開いていると、エディタの
保存で上書きされる。Windows では書き込みに失敗することもある）。

Stage01 は地面10枚とも `ground_pattern_grass.tres` を見ている（前の書きかたから
切り替え済み。ゲーム中の画面で、10枚とも .tres の絵で描かれ、カメラが 500px 動くと
模様が 30px ずれることを確かめた）。

#### 模様の絵と、継ぎ目の消しかた

貼っているのは `resources/texture/pattern/ground_grass_pixel.png`（128px）。
元絵から2段階で作る。

| ファイル | | 作りかた |
| --- | --- | --- |
| `ground_grass.png` | 512px | 元絵。四辺が繋がっていない |
| `ground_grass_seamless.png` | 512px | 継ぎ目を消した（`make_seamless.py`） |
| `ground_grass_pixel.png` | 128px | ドットを4倍に粗くした（`pixelate.py`）。**これを貼る** |

```
python tools/make_seamless.py resources/texture/pattern/ground_grass.png resources/texture/pattern/ground_grass_seamless.png
python tools/pixelate.py resources/texture/pattern/ground_grass_seamless.png resources/texture/pattern/ground_grass_pixel.png 4 --nearest
```

粗くするのは継ぎ目を消したあと。整数倍で縮めるので、継ぎ目の無さは保たれる。
`--nearest` は元の色をそのまま残す（粒立ちが強い）。外すと平均（なめらか）になる。

```
python tools/make_seamless.py <入力.png> <出力.png> [帯の幅]
```

やっていることは2つ。

1. **どこで切るかを選び直す。** 縦横それぞれ一番繋がっている場所を探して、
   そこが端に来るようにずらす。もとの四辺は内側へ回り、真ん中にあった柄は
   四隅へ回ってタイルをまたいで繋がる
2. **内側へ回った継ぎ目を、絵の別の場所から持ってきた帯で覆う。** 帯の真ん中ほど
   持ってきた絵、端へ行くほど元の絵。画素ごとにどちらかを選ぶ（混ぜない）ので
   ドット絵がぼやけない。選びかたはなだらかな乱数なので、境目がまっすぐな線に
   ならず草のむらに紛れる

鏡で折り返すやりかたも試したが、左右対称の柄（蝶の羽のような形）が出て
継ぎ目より目立った。**ずらして持ってくる**ほうが対称にならない。

この絵は 256px のところに元から線が入っていた（貼り合わせて作られている）ので、
真ん中の線も同じように消している。探し回って一番くっきりした線を消す作りには
していない。市松模様の土の境目も同じくらいくっきり出るので、探すと絵そのものを
削ってしまう。

| | もと | 直したあと |
| --- | --- | --- |
| 端どうしの差（横 / 縦） | 28.1 / 25.9 | **6.2 / 7.2** |
| 隣り合う画素の差（横 / 縦） | 9.0 / 8.5 | 9.4 / 8.8 |

端どうしの差が「隣り合う画素の差」より小さくなっていれば、並べても継ぎ目は見えない。
継ぎ目が無いので `mirror_tiling` は切ってある（入れると左右対称の柄が出る）。

### 10.16 地面ブロックの枠線（2色の縞）

`scripts/terrain_sprite.gd`。ポリゴンの輪郭をなぞる線で、BGと足場の境目を
見やすくするためのもの。`Outline` という `Line2D` の子ノードを実行時に作って
引いている。owner を付けていないので `.tscn` には保存されず、形を直せば引き直る
（滑る面の青い線と同じ作り）。

#### 調整はこの1枚で（エディタ）

`resources/terrain_look_default.tres`（`TerrainLook`）。エディタでこれを開いて
色や長さを動かすと、**この .tres を見ている全ブロックの線がその場で変わる**。
ブロックを1枚ずつ選び直さなくてよい。

| | 既定 | |
| --- | --- | --- |
| `enabled` | on | 線を引くか |
| `color` | (0.09, 0.07, 0.05, 0.9) | 線の色。縞のときは1色目 |
| `width` | 4.0 | 線の太さ (px) |
| `striped` | on | **2色の縞にする** |
| `color2` | (0.95, 0.86, 0.35, 0.9) | 縞の2色目 |
| `stripe_length` | 14.0 | 縞1本の長さ (px)。この長さで色が入れ替わる |

仕組みは、値を変えると `TerrainLook` が `changed` を出し、それを聞いている
`TerrainSprite` が線を引き直すというもの。エディタでもゲーム中でも同じ。

#### ブロックごとに変えたいとき

ノードの `outline_look` を空にすると、そのブロックだけノード側の値を使う。
名前は .tres と対応している。

| ノード側 | .tres 側 |
| --- | --- |
| `outline_enabled` | `enabled` |
| `outline_color` | `color` |
| `outline_width` | `width` |
| `outline_striped` | `striped` |
| `outline_color2` | `color2` |
| `outline_stripe_length` | `stripe_length` |

`outline_look` が入っているあいだ、ノード側の値は見ない（インスペクタには
残るが効かない）。

#### 縞のつくり

2色を1組ぶん描いた小さな絵（幅 `長さ×2`、高さ `線の太さ`）をその場で作って、
`Line2D` に `LINE_TEXTURE_TILE` で貼っている。TILE は絵の高さを線の太さに
合わせてから長さ方向へ並べるので、**高さを線の太さと同じ px で作れば、
絵の幅がそのまま縞の長さになる**。長さ20px・太さ8px で描かせて実測したところ、
赤20px / 白20px ちょうどで出た。

絵を作り直すのは色・長さ・太さが変わったときだけ。毎フレーム作ると重い。

#### まとめて入れる

```
python tools/apply_ground_pattern.py --stripe Stage01
```

貼る対象は模様と同じ（地面らしい名前のノード。`--all` で全部）。
やっているのは、各ノードの `outline_look` に
`resources/terrain_look_default.tres` を割り当てることだけ。
色と長さはそのあと .tres 側で調整する。

**太さはノードのローカル px。** 本編の Gfx ブロックは縦横別に拡大されている
ものが多いので（Stage04 の `(0.28, 2.6)` など）、ブロックによって線の太さと
縞の長さが違って見える。揃えるなら、青い滑り線（10.14）と同じように
ワールド px で引き直す必要がある。

### 10.17 中景の滝（流れる水）

`resources/shader/waterfall.gdshader`。すぐ使える形にしたマテリアルが
`resources/waterfall_material.tres`。絵を用意しなくても、矩形を置くだけで
水が落ち、滝つぼで泡としぶきが立つ。

#### 置きかた（エディタ）

1. `scenes/Background.tscn` の `Mid`（中景の `Parallax2D`）の子に `ColorRect` を足す
2. `material` に `resources/waterfall_material.tres` を貼る
3. 位置と `size` で形を決める。**上端が落ち口、下端が滝つぼ**。
   水の帯は矩形の真ん中に `width_ratio` の幅で落ち、左右の余白は
   滝つぼの泡としぶきが広がる場所になる。縦長の矩形が向いている
   （確認は 400×560 px で行った）

矩形の大きさはシェーダーが自分で割り出すので、大きさを変えても
値を入れ直す必要はない。滝を2本置いて別々に調整したいときは、
マテリアルを「ユニーク化」してから値を変える（同じ .tres を見ている滝は
全部いっしょに変わる）。

**重なり順に注意。** `Mid` の絵（`Image` という Sprite2D）は実行時に
`BgLayer` が最後の子として作るので、何もしないと滝は中景の絵の**後ろ**に回る。
中景の絵の木や草の手前に出したいときは、滝の `z_index` を 1 にする。
`Mid` は横に繰り返すので、滝も繰り返し幅ごとに1本ずつ出る。

#### それらしく見せている仕掛け

| | |
| --- | --- |
| 重力で加速する | 模様を「落ちた距離の平方根」で読んでいる。自由落下では √(y + y₀) が時間に比例して増えるので、こうすると模様が本当の落下と同じ速さで動き、筋は上で短く、下ほど引き伸ばされる |
| 落ちるほど白くなる | 上は澄んでいて後ろが透け、落ちるにつれて空気を含んで白くなる |
| 縁がちぎれる | 帯の縁は揺らぎ、細い筋に分かれる |
| 後ろがゆがむ | 水を通して見える景色を少しずらしている（`refraction`） |
| 光 | 落ち口の盛り上がりが光り、小さなきらめきが水と一緒に落ちる |
| 滝つぼ | 泡が湧き上がり、しぶきが横へ広がりながら立ちのぼる |

#### 調整できる値（主なもの）

| グループ | 値 | 既定 | |
| --- | --- | --- | --- |
| shape | `width_ratio` | 0.5 | 水の帯の幅（矩形の横幅に対する割合） |
| | `spread` | 0.2 | 下へ行くほど広がる量 |
| | `edge_wobble` | 0.12 | 縁のゆらぎ |
| | `bottom_fade` | 0.04 | 矩形の下端をぼかす高さ。手前の絵で隠れるなら 0 |
| flow | `speed` | 1.0 | 全体の速さ |
| | `gravity` / `start_speed` | 700 / 80 | 加速のつき方。重力を上げると下で速くなる |
| | `streak_width` / `streak_length` | 7 / 1.0 | 水の筋の太さ (px) と長さ |
| colors | `deep_color` / `water_color` / `foam_color` | 青緑 / 水色 / 白 | |
| | `clarity` | 0.45 | 上のほうで後ろが透ける量 |
| | `aeration` | 0.65 | 落ちるほど白く泡立つ量 |
| | `lip_glow` / `sparkle` | 0.55 / 0.5 | 落ち口の光 / きらめき |
| pool | `foam_height` / `foam_spread` | 0.14 / 0.8 | 泡の高さ / 横への広がり |
| | `mist_amount` / `mist_height` | 0.55 / 0.35 | しぶきの濃さ / 立ちのぼる高さ |
| look | `refraction` | 3.0 | 後ろのゆがみ (px)。0 で切る |
| | `pixel_size` | 0 | ドットの大きさ。0 でなめらか |
| | `color_steps` | 0 | 色の段数。0 でなめらか |

#### ピクセルアートの背景に合わせる

中景の絵は2倍で出ているドット絵なので、なじませたいときは
`pixel_size` を 2〜3、`color_steps` を 6〜10 にする。段にするのは明るさだけで、
色あいは変えない（R/G/B を別々に段にすると白の近くで紫やピンクが出たので、
そうしている）。

#### 作るときに直したこと

- **滝の途中に煙のような渦が出ていた。** 滝つぼの泡の高さを、泡の場所より上で
  0 に貼り付く値で測っていたので、そこへノイズを足すと上まで泡が漏れていた。
  上へ行くほどマイナスが大きくなる値で測るように直し、泡の盛り上がりは
  泡の高さの3割までに収まった
- 乱数は整数の PCG ハッシュ。小数の `sin`/`fract` を使うハッシュは、
  時間が経って座標が数万を超えると縞が出る

### 10.18 中景の雲（雲形ポリゴンの中で雲の絵が流れる）

`scripts/cloud_polygon.gd`（`CloudPolygon`）と `resources/shader/cloud_flow.gdshader`。
すぐ使えるマテリアルは `resources/cloud_flow_material.tres`。

#### 置きかた（エディタ）

1. `scenes/Background.tscn` の `Mid` の子にノードを足す。種類は **CloudPolygon** を選ぶ
   （Polygon2D を足して `cloud_polygon.gd` を付けてもいい）
2. 置いた時点で横長のもくもくした形が入っている。「ポリゴンを編集」で頂点を
   打ち直せば好きな雲形になる。頂点はいくつでもいい
3. マテリアルは空なら `cloud_flow_material.tres` が自動で入る

形を直すと、ふちの透明がその場で付け直される。ふちのぼかし幅はノードの `feather`。

#### ふちを透明にする仕組み

ふちを溶かすには「ポリゴンのふちからの距離」が要るが、シェーダーはポリゴンの
形を知らない。そこでスクリプトが形から小さなマスク画像（内側が白、ふちへ向かって黒、
長い辺で最大128マス）を作り、ノードのテクスチャとして渡している。マスクと UV は
実行時に作るので、インスペクタには出さず `.tscn` にも保存しない。

ふちは、マスクのぼかしに雲の明るさを混ぜて、白い雲ほど外まで残るようにしている
（`edge_breakup`）。絵が流れるとふちの形もゆっくり変わる。

#### 調整できる値

ノード側（CloudPolygon）:

| | 既定 | |
| --- | --- | --- |
| `feather` | 80 | ふちのぼかし幅 (px)。ふちからこの距離で 透明 → 不透明 |

マテリアル側（`cloud_flow_material.tres`。同じ .tres を見ている雲は全部いっしょに変わる）:

| | 既定 | |
| --- | --- | --- |
| `cloud_texture` | `cloud_sky_seamless.png` | 流す雲の絵 |
| `texture_scale` | 1.0 | 絵1px をノードの何 px で見せるか |
| `texture_offset` | (0, 0) | 絵の位置合わせ。ノードの原点に絵の縦の真ん中が来るのが 0 |
| `flow_speed` | (-6, 0) | 流れる速さ (px/秒)。マイナスで左へ |
| `edge_breakup` | 0.5 | ふちを雲の形でちぎる量。0 でなめらかなぼかし |
| `sky_cutout` | 0 | 絵の青空を透かす量。1 で雲だけ残り、BGの空になじむ |
| `opacity` | 1.0 | 全体の濃さ |
| `tint` | 白 | 色を掛ける。遠くの雲を薄く・青っぽくするのに |

雲ごとに値を変えたいときは、そのノードのマテリアルを「ユニーク化」してから直す。

#### 雲の絵

元の絵が `resources/texture/pattern/cloud_sky.png`（1024px）。空は上が濃い青、
下が淡い色なので**縦には繋がらない**。雲は横へ流すので、横だけ継ぎ目をなくした
`cloud_sky_seamless.png`（768×1024）を使っている。左右の端 256px を重ねて
なめらかに混ぜて作った（雲が溶け合うだけなので、切れ目の段は出ない）。
縦はシェーダーで繰り返さず、絵の上下の端で止めている。

色は絵のまま出る。画面いっぱいに貼って同じ範囲を比べると、平均の色が
絵 (121.1, 173.0, 203.2) に対して画面 (120.8, 172.8, 203.2) だった。

**重なり順。** `Mid` の絵（`Image`）は実行時に最後の子として作られるので、
雲は中景の絵の後ろに回る（中景の絵の上半分は透明なので空の部分では見える）。
手前に出したいときは雲の `z_index` を 1 にする。

### 10.19 起動直後のタイトル画面（ロゴと Press START）

起動すると `scenes/TitleSplash.tscn` が出る（`project.godot` の main_scene）。
大きなタイトルロゴが上から落ちてきて着地し、下に「Press START」が点滅する。
キー・パッドのボタン・クリック・タッチのどれかで、缶を開ける音とともに
ロゴが跳ね、暗くなってメインメニュー（`Title.tscn`）へ移る。
ゲームからタイトルへ戻るときは、これまでどおりメインメニューへ直接戻る。

#### ロゴの絵

元は `resources/title/title.psd`（レイヤー「枠（白フチ）」「枠（線）」「飾り」
「液体」「文字」と、隠した「元の絵」）。PSD を直したら書き出し直す:

    python tools/export_title_logo.py

`resources/title/logo/` に5枚出る。どれもキャンバスと同じ大きさなので、
重ねる位置は全部 (0, 0) のまま。

| 絵 | 重ね順 | |
| --- | --- | --- |
| `logo_backing.png` | いちばん後ろ | ロゴの形を線の茶色で塗った下地 |
| `logo_liquid.png` | | ビール・泡・粒（泡のマテリアルを掛ける） |
| `logo_text.png` | | 文字 |
| `logo_deco.png` | | 集中線・キラキラ・麦 |
| `logo_frame.png` | いちばん前 | 白フチと茶色の線 |

色の層は枠の後ろにあり、枠の線の下まで 12px 塗り広げてある。だから
`max_shift`（10px）までならずらしても隙間は見えず、枠の外にもはみ出さない。
書き出すときだけ、絵の中の小さな透明の穴をまわりの色で埋め、いちばん外側の
暗い縁（黒い背景から抜いた残り）を消している。それ以外は PSD と同じ絵。

#### 動き（`TitleLogo` / `TitleLogoLayer`）

- ふだんは上下にふわふわ浮き、少し傾く
- 3.5〜6.5 秒ごとにジャンプ（かがむ → 跳ぶ → 着地でつぶれて揺れ戻る）
- 層ごとのずれ（パララックス）は2種類:
  - ゆっくりした揺れに合わせて `depth` の分だけずれる。
    液体 -1（奥へ。枠の中で逆に動く）、文字 0.7、飾り 1.0、下地と枠は 0
  - ジャンプの勢いに `lag` の分だけ遅れてついてくる。
    液体 0.16 がいちばん大きく、跳んだとき・着地したときに中のビールが揺れる

ロゴは `scenes/TitleLogo.tscn` にまとめてあり、起動直後の画面とメインメニューの
両方がこれを置いている。値は `TitleLogo.tscn` の根（ふわふわ・ジャンプ・層のずれ）と、
`Body` の下の各層（`depth`・`lag`）で変えられ、両方の画面に効く。

メインメニュー（`title.gd`）では、ロゴを画面の上の真ん中に高さ 300px で置き、
メニューをその下（上端 360px）に並べる。落ちてくる登場は無しで、跳ねる高さは
70（起動直後の画面は 110）。OPTIONS と RANKING を開いている間はロゴを隠す。

#### ビールの泡（`beer_bubbles.gdshader`）

液体の絵の、色の濃い（黄色い）ところにだけ泡を描く。白い泡（フォーム）には
描かないので、上った泡は白い泡に吸い込まれて消えて見える。
大きい泡（ふちの光と左上の光の点つき）と細かいシュワシュワの2種類が、
列ごとに少し違う速さで上り続ける。明るさの波もゆっくり下から上へ流れる。
数・大きさ・速さは `Liquid` のマテリアルで変えられる（単位は絵の px）。

#### 背景（`title_sunburst.gdshader`）

ロゴの後ろから水色の放射状の光がゆっくり回り、うすい輪の泡が上っていく。

#### イベント版の名前入力

最初のリリースはイベント版。`project.godot` の `popping/event_version` が
`true` のあいだは、起動画面で START を押してメインメニューに入ったときに
「ENTER YOUR NAME」のパネルが出る。会場で遊ぶ人が入れ替わるたびに、
ランキングに載る名前を入れてもらうため。

- 欄は空で始まり、いまの名前が薄く出ている。Enter か OK で決まる
- 空のまま決めると、いまの名前のまま
- 決めた名前はすぐ保存され、メニュー下の PLAYER NAME 欄にも反映される
- ゲームからメニューへ戻ってきたときは出ない（起動画面を通ったときだけ）

通常版にするときは `event_version` を `false` にする
（エディタの「プロジェクト設定」で「高度な設定」をオンにすると popping の下に見える）。

#### 曲（水都オーディナリィ）

起動画面とメインメニューでは、アルバム OberSun の「03 水都オーディナリィ」を流す
（`scripts/title_music.gd` の `TitleMusic`、BGM バス）。

- ルートに1つだけ置くので、起動画面 → メインメニューへ移っても途切れない。
  メニューの中（OPTIONS・ランキング）でも続く
- ゲーム・リプレイへ移ると 0.6 秒でフェードして消える。メニューへ戻ると頭から流れ直す
- クレジット中はツリーが止まるので一緒に止まり、終わると続きから鳴る

曲は前半（3〜122秒）と後半（104秒〜）がほぼ同じ繰り返しになっている。
そこで、ファイルを 209.24 秒で切り、最後まで行ったら 107.83 秒へ戻す
（`title_suito.ogg.import` の `loop=true` と `loop_offset`）。戻り先は、切った所と
波形が一番よく合う所（相関 0.94）で、つなぎ目は 0.08 秒だけ重ねてならしてある。
元の曲の最後のフェードアウト（215秒〜）は使わない。

音量は元の曲より 6dB 下げて、ステージの BGM（-14 LUFS 前後）にそろえた。
作り直すときは、元の mp3 から同じ手順で切り出す（切る所・戻る所・下げる量は上の数字）。
